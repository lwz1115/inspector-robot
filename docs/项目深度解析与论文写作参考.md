# 园区巡检机器人项目深度解析（论文写作参考）

## 1. 项目定位与总体目标

本项目是一个面向园区场景的移动巡检机器人系统，形成了**端到端闭环**：

- 底层硬件：`STM32` 负责运动控制、传感器采集、实时任务调度；
- 中间层：`ROS`（Jetson）负责感知、定位建图、导航与跨节点通信；
- 平台层：`Spring Boot` 负责数据接入、业务接口与事件分发；
- 应用层：`Web 控制台 + UniApp 小程序`负责监控、操作、可视化与交互。

系统核心目标是：在真实网络与硬件条件下，实现巡检数据上云、视频监控、人脸识别告警、路径规划与远程目的地下发。

## 2. 代码仓库结构解读（按工程角色）

> 说明：本次梳理重点分析了业务源码与配置，未把 `node_modules`、`unpackage/dist`、第三方驱动库的全部实现逐行展开。

### 2.1 ROS 工作空间

- `ROS/src/camera_pkg`：摄像头采集、人脸识别、人脸训练节点。
- `ROS/src/http_pkg`：ROS 侧 HTTP 推送节点（机器人数据、地图）到后端。
- `ROS/src/packet_pkg`：串口协议对接 STM32，发布电压/IMU/环境数据。
- `ROS/src/gps_driver`：GPS 采集与坐标系转换（WGS84 -> GCJ02）。
- `ROS/src/n10_slam`：SLAM 建图、导航 launch、里程计节点。
- `ROS/src/n10_pkg`：路径规划与导航控制（订阅目的地与规划路径）。
- `ROS/src/lsx10`：雷达驱动与消息定义（第三方/厂商代码）。

### 2.2 后端工程（Spring Boot）

- 路径：`ROS/find_robot`
- 核心角色：
  - `controller`：REST/SSE 接口层（数据、地图、人脸、导航、认证等）。
  - `service`：业务层（ROSBridge 订阅、目的地下发、数据库业务）。
  - `entity/repository`：数据实体与 MyBatis-Plus 数据访问。
  - `resources/static`：Web 前端静态页（控制台）。

### 2.3 前端

- Web：`ROS/find_robot/src/main/resources/static`
  - 页面：`index.html`（多页面控制台）
  - 模块脚本：`dashboard.js`、`video.js`、`location.js`、`rviz.js` 等
- 小程序（UniApp）：`ROS/WeChat`
  - 页面：登录、设备、导航、个人中心、主题等
  - 后端地址统一配置：`config/server.js`

### 2.4 STM32 固件

- 路径：`ROS/STM32`
- FreeRTOS 任务组织清晰，`USER/main.c` 启动多个任务，包括平衡控制、IMU、显示、通信等。

## 3. 系统运行链路（论文可直接画图）

## 3.1 机器人状态上报链路

1. STM32 采集传感器数据并经串口发送；
2. `packet_pkg/src/serial_node.cpp` 解析帧后发布 ROS 话题（电压、温湿度、烟雾等）；
3. `http_pkg/scripts/http_node.py` 订阅 `/gps_data`、`/battery_voltage`、`/recognized_face_name` 等；
4. 定时 `POST /api/robot-data/push` 到后端；
5. Web 前端轮询读取后展示在数据看板（电量、延迟、烟雾告警、识别事件）。

## 3.2 人脸识别链路

1. `camera_pkg/scripts/face_node.py` 订阅 `/image`，处理后发布 `/recognized_face_name`；
2. 训练节点 `face_trainer.py` 通过 `/face_train_cmd` 控制采集并发布训练进度；
3. 后端 `RosbridgeSubscriber` 连接 `rosbridge`，订阅上述话题；
4. 后端 `FaceEventBroadcaster` 通过 SSE 推送给前端；
5. Web 前端 `video.js` 实时叠加识别结果与训练进度。

## 3.3 地图链路

1. Gmapping 产出 `/map`；
2. `http_pkg/scripts/map_node.py` 将栅格地图转 PNG(base64) 并 `POST /api/map/push`；
3. `MapController` 缓存最新地图并 SSE 广播；
4. Web 室内建图页实时可视化。

## 3.4 目标点下发链路

1. 前端位置页/小程序选定目标；
2. 调用后端 `/api/destination/set`；
3. 后端 `RobotHttpService` 向 Jetson 侧转发；
4. ROS 导航节点接收目标并执行路径跟踪与避障。

## 4. 关键技术点总结（论文“方法与实现”可用）

## 4.1 多端融合架构

- 不是单一 ROS demo，而是完整的“端-边-云-端”体系；
- 同时支持 Web 运维界面与移动端小程序，增强工程实用性。

## 4.2 感知与控制并行

- 摄像头、人脸识别、GPS、烟雾、电源、雷达等多源数据并行采集；
- 底盘控制与上层策略解耦：STM32 做实时控制，Jetson 做智能决策。

## 4.3 实时事件推送

- 识别和训练状态通过 `SSE` 实时推送（低实现复杂度，前端接入轻量）；
- ROS <-> Web 通过 `rosbridge + 后端转发` 打通。

## 4.4 地图数据网络化

- 将 ROS OccupancyGrid 转图像并上推后端，降低前端解析门槛；
- 便于 Web 端可视化、日志存档、远程监控。

## 4.5 导航与路径机制

- 支持目标下发、步行路径参考（高德 API）、ROS 路径跟踪、激光避障；
- 同时具备“规划路径优先 + 简单控制兜底”的容错逻辑。

## 6. 当前工程风险与改进建议（论文“不足与展望”可用）

## 6.1 安全与配置管理

- `application.properties` 中存在数据库和邮箱敏感信息明文配置（高风险）；
- 建议：改为环境变量/配置中心，仓库仅保留模板配置。

## 6.2 接口契约一致性

- 部分前端以 JSON 方式调用目的地下发，但后端控制器参数是 `@RequestParam`；
- 建议：统一改为 DTO + `@RequestBody`，避免端侧兼容问题。

## 6.3 Python 版本与环境

- 代码中同时存在 Python2 风格兼容与 Python3 脚本；
- 建议：统一迁移 Python3，并形成 requirements 与 docker 化运行环境。

## 6.4 可观测性与测试

- 目前偏“功能跑通”，自动化测试与性能基线不足；
- 建议：补充接口测试、ROS 节点仿真测试、端到端压力数据。

## 6.5 导航控制精度

- 路径跟踪控制逻辑较基础（启发式），参数固定；
- 建议：引入更标准的局部规划/轨迹跟踪控制器并做参数对比实验。

## 7. 论文实验设计建议（非常关键）

建议至少准备 4 组实验，每组都要给出指标、过程、结果表格：

1. **定位/导航性能**
   - 指标：到达成功率、平均路径偏差、到达时间、避障成功率；
2. **识别性能**
   - 指标：准确率、误报率、漏报率、平均响应时延；
3. **系统实时性**
   - 指标：传感器到前端显示延时、SSE 推送时延、控制指令下发时延；
4. **系统稳定性**
   - 指标：连续运行时长、丢包率、异常恢复时间（网络中断/节点重连）。

可加入对比实验：

- 有无路径规划；
- 不同雷达参数（帧率、范围）；
- 不同人脸阈值（confidence threshold）；
- 不同网络环境（本地直连/局域网多跳）。
