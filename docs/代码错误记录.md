## 🔴 严重问题（安全 / 功能风险）

### 1. 硬编码敏感凭证

**文件**：`src/aliyun_pkg/src/aliyun_node.py` 第 17–22 行

```python
# ❌ 当前写法
self.options = {
    'productKey': 'j1nzhwCFtTs',
    'deviceSecret': 'b2cabe2b59c49de7166949326ba1b791',
    ...
}
```

设备密钥明文写入代码，代码一旦泄露即可被仿冒设备接入云端。

```python
# ✅ 修改为从 ROS 参数服务器读取
self.options = {
    'productKey':   rospy.get_param('~product_key'),
    'deviceSecret': rospy.get_param('~device_secret'),
    'deviceName':   rospy.get_param('~device_name'),
    'regionId':     rospy.get_param('~region_id', 'cn-shanghai'),
}
```

在 launch 文件中通过 `<param>` 或外部 yaml 注入，避免密钥进入版本控制。

### 2. `os.system` 命令注入风险

**文件**：`battery_monitor.py`

```python
# ❌ self.port 来自外部配置，存在注入风险
os.system('sudo chmod 666 %s' % self.port)
os.system('sudo shutdown -h now')
```

```python
# ✅ 改用 subprocess，参数列表形式天然防注入
import subprocess
subprocess.run(['sudo', 'chmod', '666', self.port], check=True)
subprocess.run(['sudo', 'shutdown', '-h', 'now'], check=True)
```

### 3. Python 版本混用导致运行时崩溃

**文件**：`src/camera_pkg/src/face_node.py`

`face_node.py` shebang 为 `#!/usr/bin/env python`（Python 2），同时强制追加 Python 2.7 dlib 路径：

```python
sys.path.append('/home/jetson/.local/lib/python2.7/site-packages')
```

而 `launch/start_all.launch` 设置了全局环境变量：

```xml
<env name="ROS_PYTHON_VERSION" value="3"/>
```

两者直接冲突，`face_node` 在该 launch 下必然崩溃。需统一 Python 版本：要么全部迁移到 Python 3 并重新编译 dlib，要么去掉 `start_all.launch` 中的全局版本覆盖。

---

### 4. `base_control.launch` 文件内容损坏

**文件**：`src/n10_slam/launch/base_control.launch`

文件内容是一段 shell heredoc，不是合法 XML，`roslaunch` 无法解析：

```bash
# ❌ 文件实际内容
cat > ~/catkin_ws/src/n10_slam/launch/base_control.launch << 'EOF'
<?xml version="1.0"?>
...
EOF
```

需将文件替换为正确的 XML launch 内容。

## 🟠 重要问题（逻辑 / 架构缺陷）

### 5. 串口控制节点代码重复

`n10_slam/scripts/jetbot_serial_control.py` 与 `packet_pkg/src/serial_node.py` 是同一个 `JetBotSerialControl` 类的两份拷贝，协议完全相同，但存在细微差异：

| 差异点 | `n10_slam` 版本 | `packet_pkg` 版本 |
|--------|----------------|------------------|
| 初始化等待 | `rospy.sleep(11)` | `rospy.sleep(3)` |
| cmd_vel 日志 | `loginfo` | `logdebug` |
| 参数读取 | 构造函数参数 | `rospy.get_param` |

应保留一份（建议 `packet_pkg` 版本），另一个改为依赖引用，消除重复维护负担。

### 6. 三套 N10 激光雷达驱动并存

| 驱动 | 语言 | range_min | 发布范围 |
|------|------|-----------|---------|
| `n10_pkg/src/n10_node.py` | Python 3 | 0.05 m | 完整 360° |
| `n10_slam/scripts/n10_lidar_node.py` | Python 3 | 0.15 m | 前 180° |
| `lsx10/lslidar_driver` | C++ | 0.15 m | 完整 360° |

三套驱动参数不一致，职责不清。建议统一使用官方 C++ 驱动 `lslidar_driver`，删除两个 Python 实现。

### 7. 里程计使用指令速度而非编码器反馈

**文件**：`src/n10_slam/scripts/odometry_node.py`

```python
def vel_cb(self, msg):
    self.vx  = -msg.linear.x   # ❌ 订阅的是指令速度 /sensor/cmd_vel
    self.vth = -msg.angular.z  #    不是编码器实际速度
```

用指令速度积分里程计会快速累积误差，严重影响 GMapping 建图质量。应订阅 STM32 上报的实际编码器速度话题。

---

### 8. 路径跟踪角度控制逻辑错误

**文件**：`src/n10_pkg/src/navigation_controller.py`

```python
desired_angle  = math.atan2(delta_lat, delta_lon)  # 绝对目标角度 [-π, π]
angular_speed  = desired_angle * 2.0               # ❌ 未减去当前朝向，不是角度误差
```

`atan2` 返回的是目标方向的绝对角度，控制量应为 `desired_angle - current_heading`，否则机器人会持续原地旋转。

---

### 9. 路径规划坐标系错误

**文件**：`src/n10_pkg/src/path_planner.py`

```python
self.grid_resolution = 10.0  # 声称 10 米/格
# 但实际将经纬度差值直接映射到网格
# 1° 纬度 ≈ 111,000 m，精度完全失真
```

A* 规划出的路径在实际地理空间中无意义。需先将经纬度转换为局部平面坐标（如 UTM 或以起点为原点的米制坐标），再进行网格规划。

### 13. 裸 `except` 吞掉所有异常

```python
try:
    ...

# ✅ 至少捕获 Exception 并记录日志
except Exception as e:

    return None
```

### 14. `lslidar_driver/package.xml` 使用废弃的 format 1

```xml
<!-- ❌ 缺少 format="2"，使用已废弃的 run_depend -->
<package>
  <run_depend>roscpp</run_depend>
```

```xml
<!-- ✅ -->
<package format="2">
  <exec_depend>roscpp</exec_depend>
```

其余所有包均已使用 format 2，建议统一。

---

### 15. `start_all.launch` 的 `start_delay` 参数无效

```xml
<!-- ❌ ROS 不会自动处理此参数，节点仍会立即启动 -->
<param name="start_delay" type="double" value="5.0"/>
```

实现延迟启动的正确方式：

```xml
<!-- ✅ 方式一：launch-prefix -->
<node ... launch-prefix="bash -c 'sleep 5; exec $0 $@'"/>

<!-- ✅ 方式二：在节点代码中读取参数 -->
<!-- rospy.sleep(rospy.get_param('~start_delay', 0.0)) -->
```

---

### 16. GUI 节点未隔离 ROS 回调线程

**文件**：`src/n10_slam/scripts/robot_control_gui.py`

ROS 订阅回调与 Qt 主事件循环运行在同一线程，高频消息（如 `/scan`）会导致 GUI 卡顿。建议将 `rospy.spin()` 放入独立的 `QThread`，回调通过 Qt 信号槽传递数据到 UI。
